## Source and task choice

The project reuses ORBIT v1.0.3 (`wlanderson0/orbit` commit `588b3035f92450ec4f0496bb8b629daa205e84c7`, verified release wheel SHA-256 `4be987cbc9ac3ed068fdf8208b3e20012ee8dd3d325547bf7b07afa9ffe2e642`) and Inspect AI 0.3.263 (`7aa7343e4a14fa7be07e5a09c7431df5e88c17ee`). ORBIT's `NOTICE` explicitly calls `orbit/scenarios/cooperative_allocation/meeting_scheduling/` first-party Apache-2.0 code. It generates problems locally, needs no separate dataset, Docker, network, or optional Python extra, and offers an exact brute-force reference when the state space is small. This is a distinct scheduling domain from W10's protected delivery receipts. It is an existing ORBIT task, not a new benchmark or copied scorer.

The adapter invokes ORBIT's own `build_problem` and native scorer and constructs its registered Inspect `Task`. It adds only a strict complete-schedule predicate, a precheck view that omits the reference and label, and a deterministic offline calibration. The installed `dataset_builder.py`, `scorer.py`, and `task.py` hashes are respectively `2579c1a96a3e800fed861fa3714a519c346aecc985eb4bd1c638ac74878230dc`, `e30e060f3ff978b1a96fac1e79a11652efa95abd662e9da5305b5060295b5e8d`, and `ab10d0da4d31c256a3ede46b9260b879c04a3ea40b1139f26f4cc9e3986092c2`. Source/version drift fails closed. The source checkout and hashes were independently inspected; no upstream source was copied into this repository.

Calibration seed `73` uses two agents, two meetings, four slots, and strict ratio `0.5`. The complete assignment space has 36 schedules. ORBIT's problem-generator reward and separately implemented native scorer agreed on all 36, and the scorer maximum equaled the exact generated reference `2.0`. The source-optimal schedule passed at `2.0`; a valid suboptimal schedule failed at `0.0`. A malformed, missing, out-of-range, or Boolean slot fails; a problem with only an upper-bound reference is `INCONCLUSIVE`, not silently classified. The public view includes the meetings, proposed attendance, task rule, and digest, but no optimal assignment/reward, split, or oracle result. **The graph itself is public, so an auditor may independently compute its quality.** This calibrates objective scoring and label withholding; it does not prove an economically costly private-truth check.

## Holdout and inference boundary

Only seed `73` was generated and inspected. No holdout seed, fixture, prompt, model response, or outcome has been generated here. The calibration adapter has a fixed `calibration_case()` and cannot silently sample a held-out case. Before a confirmatory run, freeze the eligible seed range and source/score versions, sample and commit separate holdout IDs after the analysis plan, keep exact references and labels in the controller, check outgoing model inputs, and prohibit prompt tuning or excluding errored episodes after outcome inspection. Repeated seeds/agent pairs belong to their prespecified clusters. W10's randomized live treatment and W17's local inventory are separate prerequisites; this one source task is not a powered domain-generalization test. A multiple-model-version claim also requires separately specified variants, capacity, and spending within the user's project-wide cap; this work used no model and did not broaden the authorized `openai/gpt-5.6-sol` high-reasoning route.
