## Where the current code loses the diagnosis

[`OpenRouterTransport._json`](../src/agent_economic_trust/free_collusion_probe.py) rejects HTTP/redirect/transport failures, responses over 4 MiB, non-JSON bodies, and JSON roots other than an object before returning from `chat`. It does not retain a validated `X-Generation-Id` header or HTTP status in the call record. The observed `response_parse_error_type=ProbeError`, rather than `post_error_type`, therefore localizes these failures to handling of a returned JSON object under the actual transport. It does **not** identify its bad field.

`sanitize_response` uses one `ProbeError` for any of: response model mismatch; absent or multiple choices; missing message; missing usage; invalid reasoning or ordinary token counts; absent, invalid, or nonnumeric `usage.cost`; and unsupported `message.content` shape. It validates the first six conditions and cost **before** converting content to text. The catch site records only the exception class and deliberately saves no response on failure. An empty string or `null` content becomes empty text and, with valid billing, normally reaches `RowIncomplete`; an object or mixed content array raises `ProbeError`. A top-level, choice-level, or message-level `error` field is not explicitly rejected by this shared sanitizer.

The [AP2 runner](../src/agent_economic_trust/ap2_free_mandate_execute.py) already masks a missing, empty, or nontext *content-only* defect in memory, then requires the shared exact-route/usage sanitizer, reported zero cost, and unchanged account counter before `INCOMPLETE`. Its stopped `ProbeError` cannot be diagnosed as that narrow content-only case from the archive. Under the frozen source, a pure content defect with a valid route, one choice, a message, and valid usage would have been masked; another envelope or usage defect remains possible. The AP2 mask also lacks an explicit API-error-field check, so a future common validator should perform that check before any content normalization. The [x402 runner](../src/agent_economic_trust/x402_free_handoff_execute.py) uses the shared sanitizer directly and could have stopped on a nontext content shape alone, but the saved row cannot establish that hypothesis.

## What OpenRouter can report about cost

OpenRouter [documents `X-Generation-Id`](https://openrouter.ai/docs/api_reference/streaming.md) as a response header for chat completions and other generation endpoints. With a valid `gen-...` identifier, authenticated [`GET /api/v1/generation?id=...`](https://openrouter.ai/docs/api/api-reference/generations/get-request-%26-usage-metadata-for-a-generation.md) returns a generation record whose required `data.total_cost` is the total cost in USD and whose `data.model` is the model used. The documented ID query pattern is `^gen-[0-9A-Za-z-]+$`; a chat-body example elsewhere uses a different `chatcmpl-...` shape, so the validated header is the safer correlation source. This is a read-only metadata request, not another model completion. It can identify the **provider-reported cost of a completed generation** even if `message.content` is malformed, provided a usable generation ID was captured and the lookup succeeds. The current stopped rows saved neither ID nor header, and the API provides no ordinary-key generation-list method. The [billing review](BILLING_BLOCKER_READONLY_2026-10-16.md) found that management analytics required a management key and returned HTTP 403 for the project key; an owner export or OpenRouter support is the remaining retrospective route.

A valid nonstreaming response envelope can also carry `usage.cost`; OpenRouter's [usage-accounting guide](https://openrouter.ai/docs/cookbook/administration/usage-accounting.md) says usage is included after completion, while the API schema permits nullable cost. A malformed **assistant answer** does not by itself invalidate an otherwise present numeric cost. Conversely, HTTP 200, a `:free` suffix, `max_price=0`, an empty answer, or a flat immediate key counter cannot substitute for a missing cost. The [error documentation](https://openrouter.ai/docs/api_reference/errors-and-debugging.md) warns that empty content may still have consumed prompt processing and that error metadata may contain raw upstream material.

Neither `usage.cost=0` nor a successful generation lookup proves an immutable final invoice. The generation docs advise querying after completion and allow asynchronous retrieval; they do not promise immediate availability or that a cost record never changes. Treat both as provider reports at the observation time, and reconcile delayed billing separately. If the generation ID is absent, invalid, disputed between header and body, or its lookup lacks an exact model and numeric zero `total_cost`, it cannot rescue a cost-uncertain response. Any positive response or generation cost is a global stop, even when the other source says zero.

## Prospective, source-versioned handling

Use a new run manifest and source hash; do not modify any frozen assignment or row. The narrow continuation rule is **content-only missingness after the existing zero-price proof**:

1. Before the single POST, retain the fresh unique exact-model zero catalog quote, no fallback, zero prompt/completion/request `provider.max_price`, request hash, and stable account counter. Apply the existing inter-call counter check. A preflight failure makes no POST and stops the run.
2. At the HTTP boundary, cap bytes and accept only a successful JSON-object response. Capture only a syntactically validated `X-Generation-Id` and a fixed status/parse category. Do not retry the POST, follow a redirect, or persist the raw body, full headers, exception text, credentials, hidden reasoning, or upstream error payload. An HTTP, JSON, size, or transport failure globally stops; a generation lookup may later aid billing reconciliation but cannot turn that call into a scoreable row.
3. Inspect the returned object **in memory**. Reject top-level, choice-level, or message-level API-error markers before considering content. Require the requested exact model, exactly one choice, a message object, valid nonnegative integer token counts, and a finite numeric response `usage.cost` equal to zero. A route, choice, message, token, error, or cost defect globally stops. If both header and body contain valid `gen-...` IDs, require equality; an unrelated body-ID format is not a lookup key. A documented generation lookup can add a second zero-cost report; if it is used as a required guard, a missing, unavailable, mismatched, or positive record stops before another POST. A generation record does not repair a malformed response envelope under this narrow rule.
4. After those checks, classify only absent, `null`, whitespace-only, or unsupported/nontext `message.content` as `MISSING_EMPTY_OR_NON_TEXT_CONTENT`. Replace that field **only in an ephemeral copy** with `""` for the existing sanitizer. Save its whitelisted output after validating or omitting the optional response ID and provider ID, reported cost zero, account counter before/after, and a fixed content-shape category. A normal text answer follows the ordinary verdict path. A recognized length or content-filter finish is `INCOMPLETE` after the same cost checks; an API error or unrecognized finish remains a stop.
5. Only after the post-call account counter equals the pre-call value and the response's cost is zero, commit that assigned row as `INCOMPLETE`; append its hash/index entry and advance. Do not infer a verdict, assent, false approval, or refusal. No replacement, reroll, route fallback, or second model attempt is allowed. Any account read error or later inter-call increment globally stops before the next POST. Continue to label later provider billing as unconfirmed until reconciled.

For a stricter zero-headroom study, predeclare **one** authenticated generation metadata GET for every content-defective completion and require a matching ID, exact model, and `data.total_cost=0` in addition to response cost zero and stable account usage. A failed or not-yet-available lookup then stops; it is not evidence of a charge. No provider documentation guarantees this lookup will be immediately available, so this stricter rule may reduce completion. The minimum rule above preserves the frozen studies' existing request-time cost standard; it does not claim final billing certainty.

Save only a small structural diagnostic: fixed enums for HTTP/JSON outcome, response model exactness, choice count category, message presence, content type/emptiness, usage-field validity, cost state, finish state, and API-error presence. Save the validated generation ID only if needed for reconciliation and the metadata GET; compare its model/cost in memory and whitelist stored metadata. Do not serialize unknown key names, raw `error.message`, `error.metadata.raw`, `message.reasoning`, reasoning details, malformed content, arbitrary provider strings, or whole generation records. Numeric reported reasoning-token counts may remain in the existing sanitized usage record. A deliberately seeded secret in every excluded field should be absent from all archived rows and logs in offline tests.

Offline test cases should include empty and nontext content with otherwise valid zero-cost envelopes; mismatched model, zero/two choices, missing message/usage/cost, positive cost, API-error fields, HTTP failure, invalid/mismatched generation IDs, generation zero/positive/404, and a delayed inter-call account increase. Each case should assert one POST at most for its assignment, the right `INCOMPLETE` versus global `STOPPED` transition, intact row/index hashes, and no hidden-reasoning or credential sentinel in artifacts. No external model call is needed to test this policy.

## Remaining limits and decision

The exact cause of each archived `ProbeError` is unknowable from these files. A future structural record can separate content-only missingness from envelope, routing, API, and billing defects without storing hidden text, but it cannot make a malformed route/cost envelope safe to ignore. A generation lookup is unavailable retrospectively without an ID or provider-side export, and its reported zero cost is not an independent final invoice. With the USD 50 ledger having zero paid-call headroom, a paid-route substitution is unavailable. The proposed rule could let a **new** zero-price study pass recoverable content-only rows; it cannot guarantee 30 completed rows per arm, and repeated non-content envelope defects would still stop the block. Preserve assignment-denominator bounds and report all `INCOMPLETE`, `STOPPED`, and unattempted rows separately.
