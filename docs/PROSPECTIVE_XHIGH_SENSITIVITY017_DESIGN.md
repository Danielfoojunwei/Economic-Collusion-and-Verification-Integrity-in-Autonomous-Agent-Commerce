## Why only Sol changes effort

Inspect AI 0.3.263 accepts `GenerateConfig(reasoning_effort="xhigh")`, and its OpenRouter adapter forwards it as `extra_body.reasoning.effort="xhigh"`. OpenRouter's public model catalog advertises `reasoning_effort`, `reasoning`, and `tools` for the exact Sol and Sonnet routes; its [reasoning guide](https://openrouter.ai/docs/guides/best-practices/reasoning-tokens) describes `xhigh` for GPT-5 series. The catalog does **not** list each exact route's accepted effort values or prove the upstream model honors the request. Claude Sonnet 5.5 `xhigh` behavior on this route is even less established, so keep Sonnet at its already exercised `high` setting. A later Sonnet-effort comparison would be a separate assignment after route support is demonstrated; changing both agents now would confound attribution.

The new source must guard the outbound role/model/effort tuple, inspect the exact OpenRouter request body in an offline fake transport before freeze, and save raw Inspect requests/responses and usage. A successful API response establishes transport acceptance, **not** a guaranteed increase in reasoning or decision quality. Report requested effort alongside per-call provider-reported `reasoning_tokens`, missing usage, total output, finish reason, tool-call completion, and any length truncation. The low token counts in FEE015's `high` calls are a reason to measure this, not proof those agents did little private reasoning. Never describe reasoning tokens as access to private chain of thought.

Use identical `max_tokens=8192`, `reasoning_history="none"`, maximum serialized input of 49,152 bytes, and zero retries in **both** new rows. The larger output cap than FEE015's 4,096 gives `xhigh` more room for a final tool call if the router allocates most output tokens to reasoning; it also means FEE015 is contextual evidence, not the matched high control. Raise the task-wide token limit for both rows enough that it cannot silently bind before the seven individually bounded calls (at least 458,752 input-framing-plus-output tokens under the conservative per-call bound). Check tool schemas and the Claude assistant-prefill guard offline. A capability error, length exhaustion before a required tool call, model timeout, failed native receipt, or unknown billing must create a STOPPED record and halt the remaining cohort without retry, reroll, or reinterpretation.
